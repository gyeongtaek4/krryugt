# 데이터·계산·마감 규칙

기준일: 2026-09-17. 원칙과 현재 구현을 구분한다. 미결정 규칙을 승인 없이 구현하지 않는다.

## 적용할 기본원칙

- 현재 차량·계약·담당자 정보와 월별 확정자료를 분리한다.
- 업로드일과 귀속월은 다르다. 8월 자료를 9월에 올려도 8월 자료로 보관한다.
- 새 월 업로드는 다른 월 확정자료를 삭제하지 않는다.
- 조직은 사용자가 업데이트한 차량정보를 기준으로 매칭한다. 월중 이동의 날짜별 배분은 하지 않는다. 확정 당시 조직정보를 보관하며 이후 업데이트가 과거 확정본을 변경하지 않는다.
- 비용과 운행 마감 상태는 별도로 관리한다.
- 관리자 정정은 사유·처리자·처리일·버전을 남기고 이전 확정본을 보존한다. 재확정 전에는 직전 확정본을 보고 기준으로 한다.
- 번호는 공백 등을 정규화해 매칭한다. 미매칭·중복·누락은 검토 상태로 표시한다.

## 계산 요구와 미결정

| 항목 | 기준 또는 미결정 |
|---|---|
| 렌트 계약금액 | 저장된 모든 계약의 월 렌탈료 합계. 계약 유효일로 자동 제외하지 않는다 |
| 월별 실제 비용 | 부가세 포함 확정 렌탈료·주유비·통행료·주차비. 사용월/청구월·환급 기준은 미결정 |
| 그래프 큰 평균값 | 조회범위 내 마감 확정월 렌트비 합계 / 해당 확정월 수. 미마감 월은 합계·분모 모두 제외. 확정 0원 월은 포함 |
| 평균선 | 같은 조회범위 전체 평균을 나타내는 고정 수평선. 3개월 이동평균은 사용하지 않는다 |
| 증감 | 차액 = 대상월 - 비교월. 비교자료 없음·0원 분모는 별도 상태로 표시하는 방안 |
| 주행거리 | 입력값은 차량별 월 이동거리. 누적값 차이를 계산하지 않고 월 이동거리 자체를 집계한다 |
| 차량 운행일수 | 월 이동거리만으로는 계산 불가. 실제 일수 입력 또는 일별 자료가 추가로 필요 |
| 조직 이동 | 사용자 업데이트 기준의 차량정보로 매칭. 월중 일자별 배분 없음 |
| 보고 형식 | 인쇄용 보고서. 용지·세부 지표·레이아웃은 후속 제안 |

미집계와 0원은 구분한다. 확정월이 없으면 평균은 0원이 아니라 자료 없음으로 표시한다.
월 이동거리의 대상 월 지정 방식과 동일 차량·월 중복 자료 처리 방식은 익명 샘플로 확정한다. 기존 운행일자를 실제 운행일수로 간주하지 않는다.

## 현재 구현의 한계

- 2026-09-17 적용: 월 이동거리 합산, 차량·월 중복 차단, 확정월 전체 평균선, 인쇄 보고서 구현. 날짜 열은 기존 호환을 위해 유지하며 해당 날짜의 월을 귀속월로 사용한다.
- 보관 형식은 fleet-driving-monthly-v2로 구분한다. 이전 v1은 안내 후 불러오기를 거부하며 원본 파일은 삭제하지 않는다. 자동 변환·이전 버전 전용 조회는 미구현이다.
- 브라우저 메모리와 확정 JSON 보관·복원 방식이며 서버 영구 저장이 아니다.
- 이전 코드의 누적 키로수 최대/최소 계산은 제거했다. 월 이동거리 자료만 새 형식으로 입력한다.
- 기존 JSON 누적자료를 월 이동거리 자료로 자동 재해석하지 않는다. 형식 구분과 이전 자료 호환성을 설계해야 한다.
- 3개월 이동평균선을 전체 평균선으로 변경했다.
- 실제 권한은 미구현. 인쇄 보고서 내용 생성은 확인했지만 실제 PDF 저장·인쇄 레이아웃은 미검증이다.
