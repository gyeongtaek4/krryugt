# 개발 진행 상태

갱신일: 2026-09-19. 구현 여부와 실제 검증 범위를 구분한다.

## 현재 구현

- HTML 화면 골격, CSS, 팝업, 기능 JavaScript를 분리했다. 기능별 추가 모듈화는 후속 작업이다.
- 로그인·역할·RLS, 차량현황의 Supabase 조회·추가·수정·업로드·삭제를 연결했다. 사용자가 관리자 표시와 데이터 연결을 확인했다.
- 차량계약정보의 조회·직접 입력·업로드·개별/전체 삭제를 연결했다. 저장·삭제 자동 검증은 mock 기반이며 실제 서버 권한·업로드 전 과정의 검증을 대신하지 않는다.
- 차량·계약 표 제목 필터를 통합했다. 제목은 고정하고 적용된 필터만 민트색으로 표시한다.
- 대시보드 예시값을 제거했다. 차량·계약 집계와 확정 월자료를 사용한다.
- 월 이동거리, 월자료 중복 처리, 확정월 전체 평균선과 인쇄용 보고서 코드를 적용했다. 실제 인쇄 결과는 추가 확인이 필요하다.
- 월별 비용마감 화면을 자료 준비·요약·검토/확정·보관함으로 정리했다.

## 저장 방식과 남은 작업

- 회원관리: 가입·승인·역할·비활성화 화면과 `006_members.sql`을 실제 적용했다. `007_remove_editor_role.sql`로 관리자·일반회원 두 역할만 사용하도록 전환했다. profiles 상태 열·관리 RPC·업무/Storage 정책 존재를 확인했다. 이메일 확인 설정과 신규 가입부터 승인 후 로그인까지 실사용 검증이 남았다.

- 2026-09-18 운행: 월 SUM·이용일수·20행 페이지 이동·Supabase 조회/저장 코드 배포 확인. enum 오류 수정 후 실제 SQL 실행 성공 및 표·함수·호출 권한 확인. 실제 업로드·확정·재접속·역할별 권한 검증 필요.

- 차량인수인계: 서버 표·비공개 사진 Storage·RLS를 실제 적용했고 표·버킷·정책 존재를 확인했다. 지정 인수자 동의·동의 로그용 008·009 SQL을 실제 실행했으며, 활성 회원 선택과 기존 이력 3건 중 이름이 일치한 2건의 동의 대기 전환을 확인했다. 실제 지정 계정의 동의 완료와 비지정 계정의 동의 차단 검증이 남았다.
- 관리자 이력 수정·삭제 UI와 `010_handover_admin_manage.sql`을 실제 적용했다. 관리자·일반회원 권한, 외관자료 정리의 실제 브라우저 검증이 남았다.
- Q&A·운행가이드 화면과 `011_knowledge_center.sql`을 실제 적용했다. 관리자 Q&A/PDF 등록·수정·삭제와 일반회원 검색·열람·다운로드의 실제 브라우저 검증이 남았다.

- 차량·계약: Supabase 연결.
- 비용 월별 마감: 브라우저 메모리와 JSON 보관·복원, 서버 저장은 미연결. 운행은 새 서버 코드·SQL 적용 후 실제 저장 검증 단계다.
- 확정자료의 조직정보는 보관 당시 값으로 유지한다. 관리자 정정과 재확정 기능은 기존 흐름을 유지한다.
- 새 표 생성이나 서버 구조 변경은 필요할 때 사용자와 범위를 정한다.

## 다음 확인 순서

1. 변경된 비용마감 화면의 넓은 화면·작은 화면 가독성 확인.
2. 익명 자료로 두 월 업로드·확정·과거 조회·정정 원본 유지·JSON 재접속 복원 확인.
3. 계약의 실제 서버 저장·삭제 허용/차단 확인.
4. 비용·운행 서버 저장과 버전·정정 이력 연결 범위를 협의하고 구현.
5. 확정본·대시보드·내려받기 수치 일치와 실제 인쇄 보고서 확인.

기능 요구는 requirements.md, 계산 기준은 data-rules.md, 검증 결과는 test-checklist.md를 참고한다.
