# 개발 진행 상태

갱신일: 2026-09-28. 구현 여부와 실제 운영 화면에서 확인한 범위를 구분한다.

## 현재 구현

- Supabase 로그인·역할·RLS를 연결했다. 로그인 후 10분 동안 활동이 없으면 현재 탭에서 자동 로그아웃하며, 탭이나 브라우저 창을 닫으면 로그인 정보가 남지 않는다.
- 차량현황은 본부·부·팀·CC·정/부 담당자·차량번호·차종·지역·주차장을 저장한다. 직접 등록·수정·삭제와 Excel 업로드·양식·자료 내려받기를 제공한다.
- 차량계약정보는 차량번호를 기준으로 차량현황의 조직·CC·담당자·차종을 연결해 표시한다. 직접 등록·수정·삭제와 Excel 업로드·양식·자료 내려받기를 제공한다.
- 사고접수, 차량인수인계, Q&A, 운행가이드는 Supabase 표·비공개 Storage·권한 정책을 적용했다. 작성자와 관리자의 수정·삭제 범위도 구현했다.
- 운행기록데이터와 월별 비용마감자료는 목록·업로드·조회·확정·보관 화면을 제공한다. 목록은 각각 30건 단위로 페이지 이동한다.
- 대시보드는 실제 차량·계약·확정자료를 바탕으로 차량 수, 계약금액, 만료 예정, 부서별 차량현황, 차량이용량(팀), 비용 추이를 표시한다. 상단 자동차·계약서 아이콘은 관련 화면으로 이동한다.
- 관리자 전용 `용량확인`에서 Storage·DB 사용량과 무료 플랜 기준 잔여용량을 표시하고, 80% 이상일 때 화면·상단 알림으로 경고한다.
- Vercel의 캐시 정책을 조정해 이전 HTML과 최신 JavaScript가 섞여 로그인·메뉴가 멈추던 문제를 보완했다.
- 신규 회원은 `@fujifilm.com` 이메일로만 가입하고 인증 메일 확인 후 관리자 활성화를 거치도록 화면·서버 활성화 규칙을 보강했다. 기존 Gmail 관리자 예외 등록과 Supabase 인증 메일 설정의 실제 적용은 아래 확인 항목으로 관리한다.

## 실제 적용·확인 상태

- 2026-09-26: `vehicles.cc` 열과 API 스키마 캐시 갱신을 실제 적용했고, 홈페이지와 같은 REST 요청으로 CC 조회 성공을 확인했다.
- 2026-09-27: 관리자 용량확인 RPC `019_admin_capacity_usage.sql`을 Supabase에 실제 적용했다.
- 2026-09-27: 최신 운영 배포본에서 관리자 로그인 후 차량현황·회원관리·용량확인 메뉴가 표시되는 것을 확인했다.
- 자세한 정적 검사와 실제 브라우저 확인이 남은 항목은 [검증 목록](test-checklist.md)에 기록한다.

## 남은 확인과 다음 작업

1. 실제 Chrome에서 최신 배포본 로그인·화면 이동·아이콘 바로가기 동작을 확인한다.
2. 익명 Excel로 차량·계약·운행·비용 업로드부터 Supabase 저장, 재접속 후 목록 복원까지 화면별로 확인한다.
3. 관리자·일반회원 계정 각각에서 등록·수정·삭제·다운로드 권한을 확인한다.
4. 운행·비용의 확정, 정정, 이전 확정본 유지, 과거 월 조회를 두 개월 자료로 검증한다.
5. 용량확인의 실제 사용량 수치와 80% 경고를 관리자 화면에서 확인한다.
6. Supabase의 이메일 확인·리디렉션 주소와 기존 Gmail 관리자 사용자 ID 예외 등록을 실제 적용한 뒤, 회사 메일의 가입→인증→관리자 활성화→로그인을 익명 시험 계정으로 확인한다.

기능 기준은 [requirements.md](requirements.md), 계산과 마감 기준은 [data-rules.md](data-rules.md), 실제 변경 내역은 [CHANGELOG.md](../CHANGELOG.md)를 따른다.
