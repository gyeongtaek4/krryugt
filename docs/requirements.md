# 기능 요구사항

2026-09-18: 운행 원본은 같은 차량 여러 행을 거리 합산하고 날짜 중복을 제외해 이용일수를 계산한다. 차량현황으로 조직 매칭, 월별 SUM 보관, 두 목록 20행 페이지 이동, Supabase 저장 연결 코드를 준비한다. 활성화는 driving-storage.md 참고.

2026-09-17: 차량인수인계 추가. 차량·인계자·인수자·날짜·상태·사진 기록과 상세 조회. 현재 임시 파일 보관이며 상세 범위는 handover.md 참고.
2026-09-18: 계약시작·종료월로 총 계약개월(양 끝 월 포함)과 현재 기준 잔여개월을 자동 계산해 표시한다.

2026-09-17: 운행 화면 상단은 마지막 확정 저장 자료 기준으로 표시한다. 아래 조회월과 임시 검토자료는 별도이며, 보고·확정·백업 영역을 구분한다.

2026-09-17: 선택월 비용표에 차량별 총금액과 전체 합계를 제공한다. 확정 보관함은 해당 월 상세자료를 보관하고, 월별 조회·Excel 자료 내려받기를 지원한다. 저장 당시 조직·비용을 유지하며 서버 영구 저장은 아직 미연결이다.

대시보드는 코드에 포함된 예시자료를 사용하지 않는다. 현재 차량·계약은 저장된 실제 정보로 집계하고 비용·운행 보고는 실제 확정자료로 제공한다. 자료가 없으면 빈 상태를 표시한다. 새로운 테이블은 사용자가 필요한 구성을 요청할 때 설계한다. 실제 저장된 테스트자료를 자동 삭제하지 않는다.

2026-09-17 추가 구현: 차량현황·차량계약정보의 정보별 필터는 여러 조건을 동시에 적용한다. 계약은 개별 삭제와 필터에 관계없는 전체 삭제를 지원한다. 삭제는 관리자만 가능하며 전체 삭제 시 '전체삭제' 입력 확인을 받는다. 차량·비용 확정자료를 함께 지우지 않는다. 검증은 모의 삭제·필터 테스트이며 실제 DB 삭제는 수행하지 않았다.

기준일: 2026-09-17. 구현 상태는 기존 개발 가이드와 구조 기록 기준이며 이번 문서 작업에서 기능을 재검증하지 않았다.

## 사용자 확정 요구

| 영역 | 요구 |
|---|---|
| 차량·담당자 | 본부, 부, 팀, 담당자(정), 담당자(부), 차량번호, 차종, 지역, 주차장 |
| 계약 | 조직·담당자·차량, 월 렌탈료, 계약시작·종료, 총 기간·남은 기간 |
| 운행 | 차량번호·키로수·운행일 업로드, 조직 매칭, 차량별 상세와 과거 월 조회 |
| 비용 | 월도별 렌탈료·주유비·통행료·주차비 보관, 마감 확정, 관리자 정정, 증감 비교 |
| 공통 입력 | 양식 내려받기, 업로드, 자료 내려받기. 차량현황·계약은 직접 추가·수정 |
| 보고 | 현재 계약 월 렌탈료 합계, 확정 비용 추이, 차량 배치 판단용 운행 분석 |

현재 정보와 확정 과거자료는 별개로 관리한다. 새 월 업로드로 다른 월 확정자료가 사라져서는 안 된다.
Supabase 연결은 후속 단계로 진행한다.

## 현재 구현과 차이

- 2026-09-17: 월 이동거리 처리·차량/월 중복 차단·전체 평균선·인쇄 보고서 추가. 실제 확인 범위는 test-checklist.md 참고.
- 차량·계약 입력, 업로드와 내려받기, 운행 월별 조회와 확정 JSON 보관·복원, 비용 마감과 정정 모드가 구현되어 있다.
- 운행 마감 관리자 정정은 미구현이다. 비용 정정 상세 이력 조회 화면도 후속 과제다.
- 서버 영구 저장과 실제 로그인·관리자 권한은 미구현이다.
- 대시보드 일부는 예시값이다. 전체 보고 실제값 연동과 정확한 거리·이용일수 계산은 미완료다.
- 최근 실제 확인 범위는 code-structure.md를 참고한다. 구현됨과 검증 완료는 다르다.

## 사용자 결정 필요

2026-09-17 사용자 확정: 월 이동키로수, 부가세 포함, 사용자 조직 업데이트 기준, 저장된 모든 계약 합산, 미마감 월 제외·전체 평균선, 인쇄용 보고서. 상세 기준은 data-rules.md를 따른다. 요구 확정이며 코드 적용 완료를 뜻하지 않는다.

- 월 이동거리 양식의 대상 월 표시, 중복·재업로드 처리, 운행일수 자료 제공 방식.
- 비용 사용월/청구월·환급 기준과 권한별 조회·수정 범위.
- 인쇄 보고서의 지표와 용지·레이아웃.

계산 기준은 data-rules.md, 진행 순서는 roadmap.md에 기록한다.
