# 기능 요구사항

- 환경 설정 메뉴는 제거한다. 첫 로그인 화면에서 직원 회원가입을 제공하고 신규 회원은 비활성으로 등록되며 관리자가 활성으로 전환하기 전 업무자료에 접근할 수 없다.
- 관리자 전용 회원관리에서 이름, 역할(admin/viewer), 상태(활성/비활성)를 관리한다. 계정 삭제 대신 비활성화를 사용한다.
- 관리자는 본인 외 회원의 비밀번호를 초기 비밀번호 `1234`로 초기화할 수 있다. 초기화는 관리자 권한을 서버에서 확인한 뒤 실행하며, 로그인 화면에는 비밀번호 분실 시 관리자 문의 안내를 표시한다.
- 일반회원(viewer)은 차량현황, 사고접수 및 이력, 차량인수인계, Q&A, 운행가이드 메뉴를 표시한다. 차량현황은 조회 전용이며 사고접수·인수인계 기록은 등록할 수 있다. Q&A는 검색·열람만, 운행가이드는 PDF 열람·다운로드만 가능하다.
- 차량현황 상단 요약은 전체 차량 수와 함께 팀별·차종별·지역별 차량 대수를 각각 표시한다. 집계는 현재 등록된 차량 전체를 기준으로 하며, 표의 검색·필터 결과에 따라 바뀌지 않는다.
- 메뉴는 법인차량(차량현황·차량계약정보·차량인수인계)과 마감자료(월별 비용마감자료·운행기록데이터) 묶음으로 표시한다. 일반회원은 권한이 없는 마감자료 묶음 자체를 보지 않는다.
- 법인차량 묶음에는 Q&A와 운행가이드를 추가한다. Q&A는 관리자만 작성·답변·수정·삭제하고 활성 회원은 열람·검색한다. 운행가이드는 관리자 PDF 등록·삭제, 활성 회원 PDF 열람·다운로드로 운영한다.
- 법인차량 메뉴의 차량계약정보와 차량인수인계 사이에 사고접수 및 이력을 둔다. 활성 회원은 차량번호를 직접 입력해 아래 후보에서 등록 차량을 선택하고, 사고일·탑승자·대차 차량번호(선택)·사고장소·상황설명·현장 사진 또는 PDF(최대 3개)를 등록하고 이력을 조회한다. 차량 기본정보는 선택한 차량현황에서 가져와 접수 당시 스냅샷으로 보관한다. 관리자는 이력마다 처리 코멘트를 저장한다. 사고·인수인계 이력의 상세 내용은 접기 버튼으로 닫을 수 있다.
- 메뉴를 이동하면 브라우저 주소의 해시와 방문기록을 함께 갱신한다. 뒤로가기·앞으로가기는 이전·다음 메뉴 화면으로 이동하며, 이 기록은 브라우저 안에서만 처리해 Supabase에 저장하지 않는다.
- 주요 알림은 상단 종 버튼 옆 팝오버로 표시한다. 사이드바는 상단 메뉴 버튼으로만 접기·펼치기할 수 있고, 열린 상태는 해당 브라우저의 로컬 저장소에만 보관한다. 하단 데이터 기준 안내와 별도 제어 버튼은 표시하지 않는다.
- 차량·계약 저장은 로그인된 Supabase 세션이 있을 때만 완료로 처리한다. 서버 조회에 실패하면 빈 목록을 저장 결과처럼 표시하지 않고 재로그인·배포 홈페이지 새로고침 안내를 표시한다.
- 차량계약정보 Excel 업로드 양식은 차량번호·렌탈료·계약시작·계약종료 네 열만 사용한다. 차량번호가 차량현황에 등록돼 있으면 본부·부·팀·담당자·차종 등은 차량현황의 최신 정보로 자동 연결한다.
- 월별 비용마감 Excel 업로드 양식은 차량번호·렌탈료·주유비·통행료·주차비 다섯 열만 사용한다. 차량번호가 차량현황에 등록돼 있으면 본부·부·팀은 차량현황의 최신 정보로 자동 연결하며, 미등록 차량번호는 저장 전에 안내하고 차단한다.

- 대시보드 배치 순서는 design.md의 최신 대시보드 순서를 따른다. 계약만료 영역은 작은 요약으로 제공하며 기존 보고월·그래프 기준월 기능은 유지한다. 월별 렌트비용 추이는 제거하고, 비용마감 확정자료의 주유비·통행료·주차비를 최근 3~12개월 항목별 추이 그래프로 표시한다. 기간은 슬라이더로 조절하며 별도 차량 부대비용 요약 카드는 제공하지 않는다.

- 대시보드의 부서별 이용현황은 제거하고, 확정월의 차량번호별 이용일수와 월 주행거리 상위 5대·하위 5대를 제공한다. 순위표는 차량번호·확정 당시 팀명·집계값 순서의 열로 표시한다. 이용일수는 동일 차량의 서로 다른 운행 날짜 수이며, 월 주행거리는 해당 차량의 모든 운행 행을 합산한다. 계약 만료 요약은 6개월 내 대상 차량 수·1개월 내 수와 계약정보 이동 버튼만 제공하며 개별 차량 목록은 제외한다.

- 운행 상단 요약은 마지막 확정자료의 본부·부·팀 개수, 운행차량 대수, 월 총 주행거리로 구성한다. 미매칭 요약 카드는 제외한다. 차량번호 기준 조직 중복 제거 규칙은 driving-storage.md 참고.
- 운행기록데이터의 차량별 월 합계에서 차량번호를 선택하면 해당 월의 날짜별 합산 이동거리와 요일을 표시한다. 같은 차량·날짜의 여러 운행은 하루 한 줄로 합산한다.
- 일별 운행기록에서 주말과 한국 법정·대체공휴일은 빨간색으로 구분하고, 선택 차량·월의 일별 합계를 Excel로 내려받을 수 있다. 파일에는 운행일·요일·구분·일 이동거리를 포함한다.

2026-09-18: 운행 원본은 같은 차량 여러 행을 거리 합산하고 날짜 중복을 제외해 이용일수를 계산한다. 차량현황으로 조직 매칭, 월별 SUM 보관, 두 목록 20행 페이지 이동, Supabase 저장 연결 코드를 준비한다. 활성화는 driving-storage.md 참고.

2026-09-19: 차량인수인계 기록·차량 스냅샷은 Supabase 표, 외관 사진·PDF 합계 1~6개는 비공개 Storage에 저장한다. 활성 회원은 조회·신규 저장할 수 있고 담당자 자동 변경은 하지 않는다. 차량번호는 직접 입력해 일치 후보에서 선택하며, 첫 줄은 차량번호·차량 기본정보, 다음 줄은 인계일·인계자·인수자를 같은 행에 둔다. 상세 범위는 handover.md 참고.
2026-09-21: 새 차량인수인계는 이름·이메일 검색으로 활성 회원 계정을 인수자로 지정하고, 지정 인수자가 로그인해 동의해야 완료된다. 동의자의 이름·Auth ID·동의 시각을 서버에 남긴다. 차량번호로 과거 이력을 검색하며, 기존 기록은 인수자 이름과 정확히 일치하는 활성 회원을 자동 지정한다. 일치하지 않거나 동명이인이면 인수자 계정 미지정으로 보존한다.
2026-09-23: 차량인수인계와 사고접수 이력은 작성자가 본인 기록을 수정·삭제할 수 있고, 관리자는 모든 기록을 수정·삭제할 수 있다. 인수인계는 차량·인수자·첨부·동의 로그를, 사고접수는 차량 기본정보·첨부를 수정 대상에서 제외한다. 삭제는 확인 문구 입력을 요구한다.
2026-09-18: 계약시작·종료월로 총 계약개월(양 끝 월 포함)과 현재 기준 잔여개월을 자동 계산해 표시한다.

2026-09-17: 운행 화면 상단은 마지막 확정 저장 자료 기준으로 표시한다. 아래 조회월과 임시 검토자료는 별도이며, 보고·확정·백업 영역을 구분한다.

2026-09-17: 선택월 비용표에 차량별 총금액과 전체 합계를 제공한다. 확정 보관함은 해당 월 상세자료를 보관하고, 월별 조회·Excel 자료 내려받기를 지원한다. 저장 당시 조직·비용을 유지하며 서버 영구 저장은 아직 미연결이다.

대시보드는 코드에 포함된 예시자료를 사용하지 않는다. 현재 차량·계약은 저장된 실제 정보로 집계하고 비용·운행 보고는 실제 확정자료로 제공한다. 자료가 없으면 빈 상태를 표시한다. 새로운 테이블은 사용자가 필요한 구성을 요청할 때 설계한다. 실제 저장된 테스트자료를 자동 삭제하지 않는다.

2026-09-17 추가 구현: 차량현황·차량계약정보의 정보별 필터는 여러 조건을 동시에 적용한다. 계약은 개별 삭제와 필터에 관계없는 전체 삭제를 지원한다. 삭제는 관리자만 가능하며 전체 삭제 시 '전체삭제' 입력 확인을 받는다. 차량·비용 확정자료를 함께 지우지 않는다. 검증은 모의 삭제·필터 테스트이며 실제 DB 삭제는 수행하지 않았다.

기준일: 2026-09-17. 구현 상태는 기존 개발 가이드와 구조 기록 기준이며 이번 문서 작업에서 기능을 재검증하지 않았다.

## 사용자 확정 요구

| 영역 | 요구 |
|---|---|
| 차량·담당자 | 본부, 부, 팀, 담당자(정), 담당자(부), 차량번호, 차종, 지역, 주차장 |
| 계약 | 조직·담당자·차량, 월 렌탈료, 계약시작·종료, 총 기간·남은 기간 |
| 운행 | 차량번호·키로수·운행일 업로드, 조직 매칭, 차량별 상세와 과거 월 조회 |
| 비용 | 월도별 렌탈료·주유비·통행료·주차비 보관, 마감 확정, 관리자 정정, 증감 비교 |
| 공통 입력 | 양식 내려받기, 업로드, 자료 내려받기. 차량현황·계약은 직접 추가·수정 |
| 보고 | 현재 계약 월 렌탈료 합계, 확정 비용 추이, 차량 배치 판단용 운행 분석 |

현재 정보와 확정 과거자료는 별개로 관리한다. 새 월 업로드로 다른 월 확정자료가 사라져서는 안 된다.
Supabase 연결은 후속 단계로 진행한다.

## 현재 구현과 차이

- 2026-09-17: 월 이동거리 처리·차량/월 중복 차단·전체 평균선·인쇄 보고서 추가. 실제 확인 범위는 test-checklist.md 참고.
- 차량·계약 입력, 업로드와 내려받기, 운행 월별 조회와 확정 JSON 보관·복원, 비용 마감과 정정 모드가 구현되어 있다.
- 운행 마감 관리자 정정은 미구현이다. 비용 정정 상세 이력 조회 화면도 후속 과제다.
- 서버 영구 저장과 실제 로그인·관리자 권한은 미구현이다.
- 대시보드 일부는 예시값이다. 전체 보고 실제값 연동과 정확한 거리·이용일수 계산은 미완료다.
- 최근 실제 확인 범위는 code-structure.md를 참고한다. 구현됨과 검증 완료는 다르다.
