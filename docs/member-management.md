# 회원관리

## 가입과 활성화 흐름

1. 직원은 첫 로그인 화면에서 이름·`@fujifilm.com` 이메일·비밀번호로 가입한다. 다른 도메인은 화면에서 가입할 수 없다.
2. 받은 인증 메일의 링크를 열어 이메일을 확인한다. 인증 메일이 보이지 않으면 로그인 화면에 항상 보이는 `인증 메일 다시 보내기`를 사용한다. 미인증 계정이 로그인을 시도하면 같은 안내를 표시한다.
3. 신규 계정은 `viewer` 역할과 `disabled` 상태로 생성된다.
4. 관리자가 회원관리에서 역할과 상태를 정하고 `active`로 저장한다.
5. 활성 회원은 역할에 따라 업무자료에 접근한다. 일반회원도 차량현황·차량인수인계와 함께 Q&A·운행가이드를 조회할 수 있다.

## 역할과 상태

- `admin`: 회원 승인·역할 관리와 전체 관리 기능.
- `viewer`(일반회원): 차량현황 조회, 사고접수 등록·이력 조회, 차량인수인계 조회·등록, Q&A 검색·열람, 운행가이드 PDF 열람·다운로드만 가능하다. 본인이 작성한 사고접수·인수인계 기록은 수정·삭제할 수 있다. 차량 추가·수정·삭제, 다른 작성자의 기록 수정·삭제, 사고 처리 코멘트, Q&A·가이드 작성·수정·삭제, 계약·운행·비용 화면은 접근 불가다.
- `active`: 역할에 맞춰 사용 가능.
- `disabled`: 회원가입 직후 또는 관리자 비활성화 후의 상태이며, 로그인 후 업무자료 접근 불가.

기존에 활성화된 회사 외 이메일의 관리자 계정은 로그인 가능 상태를 유지한다. 이 예외는 이메일 문자열이 아니라 서버의 사용자 ID로만 별도 등록한다. 신규 회사 외 이메일 계정은 관리자가 `active`로 바꿀 수 없으므로, 화면 우회 가입만으로 업무자료에 접근할 수 없다.

현재 로그인한 관리자는 자기 계정의 역할을 내리거나 비활성화·삭제할 수 없다. 관리자는 다른 회원의 `계정 삭제`를 선택해 Auth 로그인 계정과 회원 프로필을 함께 영구 삭제할 수 있다. 사고접수·인수인계·Q&A·운행가이드 작성 이력이 있는 회원은 업무 증빙 보존을 위해 삭제하지 않고 비활성화를 안내한다.

## 비밀번호 초기화

- 관리자는 회원관리 목록에서 본인 외 회원의 `비밀번호 초기화`를 선택할 수 있다.
- 확인 후 해당 회원의 비밀번호는 관리자가 정한 초기 비밀번호로 변경된다. 이 작업은 관리자 권한을 서버에서 확인하는 `admin_reset_member_password` RPC로만 실행한다.
- 본인 계정은 이 기능으로 초기화할 수 없다. 비밀번호를 초기화한 뒤에는 대상 직원에게 안전한 방법으로 초기 비밀번호를 전달해야 한다.
- 로그인 화면 하단에는 `비밀번호 분실 시, 법인차량 관리자에게 문의 주세요.` 안내를 표시한다.

## 로그인 실패 잠금과 본인 비밀번호 변경

- 로그인 비밀번호를 틀릴 때마다 로그인 화면에 현재 `n/5회 오류`를 표시한다. 5회 연속 틀리면 회원 프로필에 잠금 상태를 저장하고 로그인 화면에서 접근을 막는다. 새로고침하거나 탭을 닫아도 잠금은 유지된다.
- 잠긴 회원은 회원관리 목록의 `로그인 잠김` 표시로 구분한다. 관리자는 해당 회원의 `잠금 해제`를 선택해 실패 횟수를 초기화할 수 있다.
- 정상 로그인에 성공하면 이전 실패 횟수는 자동으로 초기화된다.
- 로그인한 관리자·일반회원 모두 상단의 `비밀번호 변경`에서 현재 비밀번호를 확인한 뒤 본인 비밀번호를 8자 이상 새 비밀번호로 변경할 수 있다.

## 회원 목록 확인

- 상단 조회칸에서 이름, 이메일, 역할, 상태로 회원을 찾을 수 있다.
- `비활성` 회원을 첫 번째로 두고 은은한 빨간 배경과 상태 선택 표시로 구분한다. 활성 회원은 그 아래 가입일 역순으로 표시한다.
- 상단 요약에는 전체 회원 수와 `활성`·`비활성` 회원 수를 각각 표시한다.

## 서버 적용

- `supabase/006_members.sql`은 profiles의 이메일·상태, 신규 가입 트리거, 관리자 갱신 RPC, 활성 회원 RLS를 구성한다.
- 기존 profiles 회원은 실행 시 이메일을 동기화하고 `active`로 유지하여 현재 관리자가 잠기지 않게 한다.
- `supabase/012_member_status_simplification.sql`은 기존 `pending` 회원을 `disabled`로 전환하고 상태 값을 `active`·`disabled` 두 가지로 제한한다.
- `supabase/013_admin_password_reset.sql`은 관리자만 다른 회원의 Auth 비밀번호를 초기 비밀번호로 변경할 수 있는 RPC를 구성한다. service_role 키는 브라우저 코드에 넣지 않는다.
- `supabase/026_login_security.sql`은 로그인 실패 횟수·잠금 시각 열과 로그인 잠금 확인/실패 기록/성공 초기화/관리자 잠금 해제 RPC를 구성한다. 비밀번호 자체는 이 표에 저장하지 않는다.
- `supabase/027_login_failure_count.sql`은 로그인 화면에서 표시할 실패 횟수를 반환하는 RPC를 추가한다.
- `supabase/021_company_email_verification.sql`은 회사 이메일 계정만 활성화할 수 있도록 관리자 활성화 RPC를 보강한다. 기존 활성 관리자 예외는 SQL Editor에서 해당 사용자의 ID만 `profile_email_exceptions`에 1회 등록한다.
- `supabase/022_admin_member_delete.sql`은 활성 관리자가 다른 회원의 Auth 계정과 profiles를 함께 삭제하는 RPC를 구성한다. 업무 작성 이력이 있거나 현재 로그인한 관리자 본인인 경우는 서버에서 차단한다.

## 로그인 세션 보안

- 로그인 후 마우스·키보드·터치·스크롤 입력이 10분 동안 없으면 브라우저의 현재 탭에서 자동 로그아웃한다.
- 인증 정보는 탭 세션 저장소에만 보관한다. 새로고침 중에는 로그인 상태가 유지되지만, 탭이나 브라우저 창을 닫으면 다음 접속 때 다시 로그인해야 한다.
- 같은 브라우저 창에서 관리자와 일반회원을 각각 다른 탭으로 로그인할 수 있다. 로그인·로그아웃 신호는 다른 탭으로 전파하지 않도록 분리한다.
- 브라우저 강제 종료나 운영체제 종료처럼 종료 절차가 생략되는 상황까지 서버 로그아웃 요청 완료를 보장하지는 않지만, 탭 세션 저장소를 사용하므로 일반적인 탭·창 종료 후 재접속에는 기존 로그인 정보가 남지 않는다.
