# 회원관리

## 가입과 활성화 흐름

1. 직원이 첫 로그인 화면에서 이름·이메일·비밀번호로 가입한다.
2. Supabase 이메일 확인이 켜져 있으면 받은 메일에서 이메일을 확인한다.
3. 신규 계정은 `viewer` 역할과 `disabled` 상태로 생성된다.
4. 관리자가 회원관리에서 역할과 상태를 정하고 `active`로 저장한다.
5. 활성 회원은 역할에 따라 업무자료에 접근한다. 일반회원도 차량현황·차량인수인계와 함께 Q&A·운행가이드를 조회할 수 있다.

## 역할과 상태

- `admin`: 회원 승인·역할 관리와 전체 관리 기능.
- `viewer`(일반회원): 차량현황 조회, 차량인수인계 조회·등록, Q&A 검색·열람, 운행가이드 PDF 열람·다운로드만 가능하다. 차량 추가·수정·삭제, Q&A·가이드 작성·수정·삭제, 계약·운행·비용 화면은 접근 불가다.
- `active`: 역할에 맞춰 사용 가능.
- `disabled`: 회원가입 직후 또는 관리자 비활성화 후의 상태이며, 로그인 후 업무자료 접근 불가.

현재 로그인한 관리자는 자기 계정의 역할을 내리거나 비활성화할 수 없다. 사용자 삭제는 Auth 계정과 업무 감사 이력에 영향을 주므로 이번 범위에 포함하지 않고 비활성화를 사용한다.

## 비밀번호 초기화

- 관리자는 회원관리 목록에서 본인 외 회원의 `비밀번호 초기화`를 선택할 수 있다.
- 확인 후 해당 회원의 비밀번호는 초기 비밀번호 `1234`로 변경된다. 이 작업은 관리자 권한을 서버에서 확인하는 `admin_reset_member_password` RPC로만 실행한다.
- 본인 계정은 이 기능으로 초기화할 수 없다. 비밀번호를 초기화한 뒤에는 대상 직원에게 안전한 방법으로 초기 비밀번호를 전달해야 한다.
- 로그인 화면 하단에는 `비밀번호 분실 시, 법인차량 관리자에게 문의 주세요.` 안내를 표시한다.

## 회원 목록 확인

- 상단 조회칸에서 이름, 이메일, 역할, 상태로 회원을 찾을 수 있다.
- `비활성` 회원을 첫 번째로 두고 은은한 빨간 배경과 상태 선택 표시로 구분한다. 활성 회원은 그 아래 가입일 역순으로 표시한다.
- 상단 요약에는 전체 회원 수와 `활성`·`비활성` 회원 수를 각각 표시한다.

## 서버 적용

- `supabase/006_members.sql`은 profiles의 이메일·상태, 신규 가입 트리거, 관리자 갱신 RPC, 활성 회원 RLS를 구성한다.
- 기존 profiles 회원은 실행 시 이메일을 동기화하고 `active`로 유지하여 현재 관리자가 잠기지 않게 한다.
- `supabase/012_member_status_simplification.sql`은 기존 `pending` 회원을 `disabled`로 전환하고 상태 값을 `active`·`disabled` 두 가지로 제한한다.
- `supabase/013_admin_password_reset.sql`은 관리자만 다른 회원의 Auth 비밀번호를 초기 비밀번호로 변경할 수 있는 RPC를 구성한다. service_role 키는 브라우저 코드에 넣지 않는다.

### 2026-09-22 실제 적용

- Supabase SQL Editor에서 `013_admin_password_reset.sql`을 실행해 성공했다. 함수 생성·실행 권한만 적용했으며, 이 적용 과정에서 특정 회원의 비밀번호를 초기화하지 않았다.
- Secret 또는 service_role 키는 브라우저 코드에 넣지 않는다.

### 2026-09-19 실제 적용·검증

- Supabase SQL Editor에서 `006_members.sql` 실행을 성공했다. 기존 업무 원본 데이터는 삭제하지 않았다.
- 확인 쿼리에서 profiles `status` 열, `admin_update_profile` RPC, `is_active_user` 함수, 업무자료 정책 7개, 인수인계 Storage 정책 3개가 모두 `true`로 확인됐다.
- 다음 실제 사용자 검증은 직원 계정 가입 → 관리자 화면에서 `active` 승인 → 역할별 재로그인이다.

### 입력자 역할 제거

- 2026-09-19부터 역할은 `admin`(관리자)과 `viewer`(일반회원)만 사용한다.
- `supabase/007_remove_editor_role.sql`은 기존 입력자 계정을 일반회원으로 전환하고, 새 입력자 역할 저장과 관리자 외 업무자료 수정 권한을 차단한다.
- 실제 실행 확인: 입력자 계정 수 0, 역할 제약조건, 관리자 회원관리 RPC, 관리자 전용 운행 권한이 모두 `true`로 확인됐다.
