# 회원관리

## 가입과 승인 흐름

1. 직원이 첫 로그인 화면에서 이름·이메일·비밀번호로 가입한다.
2. Supabase 이메일 확인이 켜져 있으면 받은 메일에서 이메일을 확인한다.
3. 신규 계정은 `viewer` 역할과 `pending` 상태로 생성된다.
4. 관리자가 회원관리에서 역할과 상태를 정하고 `active`로 저장한다.
5. 활성 회원만 차량·계약·운행·인수인계 자료에 접근할 수 있다.

## 역할과 상태

- `admin`: 회원 승인·역할 관리와 전체 관리 기능.
- `editor`: 업무자료 입력·수정. 관리자 전용 삭제·회원관리는 제외한다.
- `viewer`(일반회원): 차량현황 조회와 차량인수인계 조회·등록만 가능. 차량 추가·수정·삭제와 계약·운행·비용 화면은 접근 불가.
- `pending`: 가입 후 승인대기. 업무자료 접근 불가.
- `active`: 역할에 맞춰 사용 가능.
- `disabled`: 로그인 후 업무자료 접근 불가.

현재 로그인한 관리자는 자기 계정의 역할을 내리거나 비활성화할 수 없다. 사용자 삭제는 Auth 계정과 업무 감사 이력에 영향을 주므로 이번 범위에 포함하지 않고 비활성화를 사용한다.

## 서버 적용

- `supabase/006_members.sql`은 profiles의 이메일·상태, 신규 가입 트리거, 관리자 갱신 RPC, 활성 회원 RLS를 구성한다.
- 기존 profiles 회원은 실행 시 이메일을 동기화하고 `active`로 유지하여 현재 관리자가 잠기지 않게 한다.
- Secret 또는 service_role 키는 브라우저 코드에 넣지 않는다.

### 2026-09-19 실제 적용·검증

- Supabase SQL Editor에서 `006_members.sql` 실행을 성공했다. 기존 업무 원본 데이터는 삭제하지 않았다.
- 확인 쿼리에서 profiles `status` 열, `admin_update_profile` RPC, `is_active_user` 함수, 업무자료 정책 7개, 인수인계 Storage 정책 3개가 모두 `true`로 확인됐다.
- 다음 실제 사용자 검증은 직원 계정 가입 → 관리자 화면에서 `active` 승인 → 역할별 재로그인이다.
