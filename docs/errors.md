# 오류 기록

## 차량현황 CC 업로드 뒤 `querySelector` 오류 (2026-09-26)

- 증상: CC 열이 포함된 차량현황 업로드 후 `Cannot read properties of undefined (reading 'querySelector')` 오류가 표시됐다.
- 원인: 차량계약정보 표의 열별 필터 위치가 기존 열 순서에 고정돼 있어, 새 CC 열을 추가한 뒤 대상 헤더를 찾지 못했다.
- 조치: CC를 포함한 계약 표의 열 위치를 다시 지정하고, 예상하지 못한 헤더 누락 시 필터 생성만 건너뛰어 업로드가 중단되지 않게 했다. 업로드 팝업의 필수 열 안내에도 CC를 추가했다.
- 검증: 첨부한 Excel은 첫 행에 CC 열과 입력값이 포함된 것을 읽기 전용으로 확인했다. 배포 후 실제 업로드 재시도는 필요하다.

## 차량현황 CC 업로드 시 스키마 캐시 열 없음 오류 (2026-09-26)

- 증상: CC 열이 포함된 차량현황 Excel을 업로드할 때 `Could not find the 'cc' column of 'vehicles' in the schema cache` 오류가 표시됐다.
- 원인: `vehicles.cc` DB 열은 생성됐지만 Supabase API(PostgREST)의 스키마 캐시가 새 열 정보를 아직 다시 읽지 않은 상태였다.
- 조치: `alter table public.vehicles add column if not exists cc text not null default '';`를 단독으로 다시 실행한 뒤 `select pg_notify('pgrst', 'reload schema');`로 API 스키마 캐시를 갱신했다.
- 검증: 배포 홈페이지와 같은 Supabase REST API의 `vehicles?select=cc` 읽기 요청이 2026-09-26 HTTP 200으로 성공했다. 사용자는 업로드 팝업을 닫고 배포 홈페이지를 새로고침한 뒤 파일을 다시 선택해 업로드한다.

## 사고접수 메뉴가 기존 안내 문구만 표시됨 (2026-09-23)

- 증상: 사고접수 및 이력 메뉴를 눌러도 “다음 단계에서 함께 만들 수 있습니다” 안내가 표시되고 접수 화면으로 이동하지 않았다.
- 원인: 메뉴 클릭 처리의 허용 화면 목록에 새 카테고리를 추가하지 않았다.
- 조치: `사고접수 및 이력`을 메뉴 이동 허용 목록에 추가해 `#accidents` 해시와 사고접수 화면을 연결했다.
- 검증: 사고 화면·권한·저장 SQL 정적 검사에 메뉴 이동 조건을 포함했다. 배포 후 실제 메뉴 클릭 확인이 필요하다.

## 차량·계약 자료가 새로고침 뒤 빈 목록으로 보임 (2026-09-22)

- 증상: 차량현황·차량계약정보를 업로드한 뒤 새로고침하면 화면의 목록이 비어 보인다.
- 읽기 전용 확인: Supabase Table Editor에서 `vehicles` 10건, `contracts` 10건이 실제로 남아 있음을 확인했다. 따라서 데이터가 자동 삭제되었거나 저장 용량 때문에 사라진 것은 아니다.
- 원인 범위: 브라우저의 로그인 세션·RLS 조회 권한 또는 홈페이지의 새로고침 후 서버 조회 흐름 문제다. 특히 `file:///.../dist/index.html` 로컬 파일 실행은 배포 홈페이지와 브라우저 저장소·로그인 상태가 분리될 수 있다.
- 조치: 서버 조회 실패 시 기존 화면 값을 임시값으로 바꾸지 않고 오류를 고정 안내한다. 로그인 직후 조회가 한 번 실패하면 0.7초 뒤 한 번만 재시도하며, 로그인 세션이 없을 때는 차량을 화면에만 임시 추가·업로드하지 않도록 차단했다. 로컬 `file:///` 미리보기에는 배포 홈페이지 사용 안내를 표시한다.
- 추가 원인 확인: 배포 홈페이지의 콘솔에서 `supabase-auth.js` 권한 메뉴 처리 중 이미 삭제된 `guideUploadButton`에 `hidden`을 설정하려는 null 오류를 확인했다. 오류가 차량·계약 조회보다 먼저 발생해, 로그인 뒤 서버 조회 함수가 실행되지 않았다.
- 추가 조치: 존재하는 권한 버튼만 표시·숨김 처리하도록 수정했다.
- 검증: 2026-09-22 배포 홈페이지에서 관리자 로그인 상태로 새로고침 후 차량 10대, 월 렌트계약금액 4,200,000원, 2026-08 확정 운행자료가 표시되는 것을 확인했다.
- 상태: 수정·배포·실제 조회 검증 완료. 기존 Supabase 행은 유지된다.

## 2026-09-21 — 009 인수인계 기존 이력 연결 SQL UUID 집계 오류

- 증상: `009_handover_consent_name_and_legacy_match.sql` 실행 시 `function min(uuid) does not exist` 오류가 발생했다.
- 원인: PostgreSQL은 UUID 자료형에 `min()` 집계 함수를 제공하지 않는다.
- 조치: 동명이인이 아닌 활성 회원의 ID를 고를 때 `min(id::text)::uuid`를 사용하도록 수정했다.
- 영향: SQL은 트랜잭션 안에서 실행되므로 실패한 실행은 롤백됐고, 기존 인수인계 데이터는 변경되지 않았다. 수정본 재실행은 성공했고, 기존 이력의 이름 일치 2건이 동의 대기 상태로 연결된 것을 확인했다.

## 승인된 신규 회원 로그인 차단 (2026-09-19)

- 증상: 관리자 화면에서 신규 회원을 `active`로 승인했지만 로그인할 수 없었다.
- 확인: 가입 계정의 profiles는 `viewer`/`active`로 정상이나 Auth의 `email_confirmed_at` 값은 비어 있었다.
- 원인: 승인 상태와 이메일 인증은 별도 절차다. Supabase Email Provider의 이메일 확인이 활성화되어 인증 전에는 비밀번호가 맞아도 로그인할 수 없다. 또한 Site URL이 `http://localhost:3000`으로 설정되어 인증 완료 링크가 존재하지 않는 로컬 서버로 향했다.
- 조치: Site URL을 실제 배포 주소 `https://krryugt-gray.vercel.app`로 변경했다. 기존 인증 링크는 만료되었으므로 새 인증 메일이 필요하다. 가입자는 새 링크에서 인증을 완료한 뒤 로그인한다.
- 상태: 리디렉션 설정 수정 완료. 새 인증 메일 수신 → 이메일 확인 → 실제 로그인 재검증이 필요하다.
