# 운행자료 집계·서버 저장

## 현재 기준 (2026-09-18)

- 한 파일은 한 달 자료. 제목은 차량번호, 키로수, 운행년월일이며 키로수는 각 운행의 이동거리다.
- 같은 차량의 모든 행을 합산한다. 동일 차량·날짜·거리 행도 제거하지 않는다.
- 차량별 이용일수는 서로 다른 운행 날짜 수다. 하루 네 번 이용해도 1일이다.
- 검토자료 조직은 현재 차량현황에서 매칭한다. 확정 시 서버에서 조회한 차량·조직정보를 복사해 이후 과거자료에 유지한다.
- 월별 보관함에는 월도·차량수·전체 거리 합계·상태·확정일을 표시한다. 차량 상세는 월도별 차량당 한 행이다.
- 각 목록은 20행씩 이전·다음 페이지를 제공한다.
- 차량별 월 합계 목록에서 차량번호를 누르면 해당 월의 일별 운행기록을 연다. 같은 차량·날짜의 여러 행은 일 이동거리 한 줄로 합산하고, 운행일·요일·일 이동거리와 월 이용일수·월 이동거리를 함께 표시한다.
- 같은 월 재업로드는 확인 후 미확정월 전체 교체. 다른 월 유지. 확정월은 서버에서 덮어쓰기 차단.
- 상단은 마지막 확정 저장 기준이며 검토자료는 아래 목록에서 확인한다.
- 상단 순서는 본부·부·팀·운행차량·월 총 주행거리. 확정자료의 정규화된 차량번호로 차량당 조직을 한 번 집계한다. 본부는 이름, 부는 본부+부, 팀은 본부+부+팀으로 중복 제거한다. 조직 누락은 개수에서 제외하고 미매칭 안내는 상세 목록에 유지한다.

## Supabase 활성화

1. SQL Editor → New query에서 supabase/003_driving_months.sql 전체를 붙여넣고 Run.
2. 홈페이지 새 코드 배포 후 새로고침·로그인.
3. 익명 월 파일 업로드 → 합계 확인 → 확정 → 새로고침 후 복원 확인.
4. 다음 월도 추가해 과거월 유지와 관리자/입력자 저장, 조회자 차단 확인.

기존 driving_records는 삭제·변경하지 않는다. 추가 driving_months 표에 월 원본 행과 확정일·처리자를 저장한다. save_driving_month 함수가 권한·날짜·마감 잠금을 검증한다.

## 구현·검증 구분

- 조회·업로드·직접 추가·확정 코드 준비 완료. 2026-09-18 enum 오류 수정 후 사용자 승인으로 실제 프로젝트의 SQL Editor에서 재실행 성공했다. driving_months와 save_driving_month 존재 및 인수·authenticated 실행 권한을 확인했다. 배포된 driving-months.js HTTP 200과 RPC 코드 제공을 확인했다. 실제 업로드·확정·재접속 및 역할별 권한 허용/차단 검증은 아직 남아 있다.
- 서버 재조회로 재접속 복원. 원본 JSON을 보관하고 차량별 합계를 계산한다.
- 이전 v2 월합계 JSON에는 실제 운행 날짜가 없어 일수로 자동 해석하지 않는다. 이전 파일은 별도 보관하고 원본 운행 파일을 업로드한다.
- 내려받기는 daily-v3 백업 형식. 이전 JSON 불러오기 버튼은 숨긴다.
- 관리자 서버 마감 정정·버전 보관은 후속 작업이며 현재 확정월은 수정 차단한다.
