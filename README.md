# krryugt

법인차량 데이터관리 홈페이지

## 개발 파일과 로컬 미리보기

- `dist/index.html`: 화면 골격 (306줄).
- `dist/css/app.css`: 디자인과 반응형 스타일.
- `dist/js/dialogs.js`: 업로드·직접 입력 팝업.
- `dist/js/app.js`: 데이터, 계산, 업로드, 조회, 마감 기능.
- 개발 원칙: `AGENTS.md`. 상세 구조와 검증 기록: `docs/code-structure.md`.
- 문서 안내: 요구사항 `docs/requirements.md`, 디자인 `docs/design.md`, 업무 규칙 `docs/data-rules.md`, 저장 구조 `docs/data-model.md`, 엑셀 형식 `docs/excel-format.md`, 오류 `docs/errors.md`, 검증 `docs/test-checklist.md`, 진행 `docs/roadmap.md`, 변경 이력 `CHANGELOG.md`.

프로젝트 폴더에서 `node scripts/preview.cjs`를 실행하고 `http://127.0.0.1:4173/`에 접속합니다.
종료는 터미널에서 Ctrl+C를 누릅니다. 별도 npm 설치는 필요하지 않습니다.
Vercel 배포에는 `dist/` 전체가 포함되어야 합니다.

## 월별 운행자료 보관

1. 운행년월일, 차량번호, 키로수(월 이동거리)가 있는 Excel을 업로드합니다. 차량별 월마다 한 행으로 작성하며 날짜의 월로 분류합니다. 다른 월 자료도 함께 유지됩니다.
2. 조회월을 선택해 부서정보와 키로수를 확인합니다.
3. 조회월 마감 확정을 누르면 당시 부서정보와 운행기록을 고정하고 수정·덮어쓰기를 막습니다.
4. 다운로드한 JSON 보관파일을 안전한 폴더에 보관합니다. 파일에는 전체 확정월 자료가 포함됩니다.
5. 다음 접속 또는 새로고침 후 보관파일 불러오기로 확정자료를 복원합니다.
6. 확정자료를 기준으로 대시보드 보고월을 조회하거나 부서별 운행보고 Excel을 내려받습니다.

Supabase 연결 전에는 홈페이지 서버에 자료를 영구 저장하지 않습니다. 확정할 때마다 최신 보관파일과 원본 Excel을 함께 보관하세요.

주행거리는 입력한 월 이동거리 자체입니다. 월자료만으로 운행일수는 계산하지 않습니다. 이전 누적거리 v1 보관파일은 새 형식으로 자동 변환되지 않으므로 원본을 보관하세요.
대시보드의 보고서 인쇄는 비용 그래프 기준월을 사용합니다. 비용은 부가세 포함으로 입력하며 별도 세금을 추가하지 않습니다.
